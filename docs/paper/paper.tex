\begin{abstract}
Modern Kubernetes-based microservice architectures face coupled reliability challenges: pre-merge code vulnerabilities and prolonged runtime incident recovery. Conventional DevSecOps practices rely either on static code linters that lack runtime operational context and cannot synthesize verifiable corrective patches, or on threshold-based autoscalers that react without root-cause intelligence or pre-actuation safety guarantees. To resolve this bifurcation, this paper presents AgentHeal, a closed-loop platform synchronizing Shift-Left pre-merge security auditing with Shift-Right telemetry-driven self-healing over a shared event bus. On the Shift-Left critical path, an automated GitHub App audits incoming pull requests against the OWASP Top 10:2021 taxonomy via abstract syntax tree (AST) grammar checks, validates dependencies against vulnerability advisories, computes quantitative compliance scores, and invokes a Gemini 2.0 Flash ReAct reasoning engine to synthesize automated corrective pull requests before enforcing a binding quality gate. On the Shift-Right critical path, a streaming digital twin ingests four-dimensional cluster telemetry, detects anomalous states via an in-memory Isolation Forest in 2.26~ms, decomposes root causes using KernelSHAP feature attribution, arbitrates remediation directives between a SimiFed federated reinforcement learning agent and an LLM reasoning agent, and validates candidate scaling actions via a SimPy $M/M/c$ discrete-event queueing simulation prior to Kubernetes cluster actuation. We evaluate AgentHeal on the Google Online Boutique microservice benchmark across four canonical failure scenarios with $N=15$ repeated trials per scenario. The Isolation Forest achieves a mean anomaly detection latency of 2.26~ms ($\sigma=0.37$~ms) with a 98.3\% overall detection rate, and autonomous remediation converges in a mean of 2.98~s ($\sigma=0.23$~s), representing a $>98\%$ reduction in recovery time compared to reactive threshold autoscalers. On a 50-PR synthetic benchmark, the Shift-Left engine achieves 98.5\% precision and 97.5\% recall, and qualitative empirical evaluation on a live public repository pull request demonstrates complete remediation of 14 injected vulnerabilities across all ten OWASP categories.
\end{abstract}

\section{Introduction}

Distributed cloud-native applications deployed on Kubernetes-orchestrated microservice architectures face two coupled reliability challenges. First, unvetted pull requests and insufficiently reviewed code changes frequently introduce security regressions and performance bottlenecks into production environments. The 2024 State of DevOps report estimates that over 60\% of unplanned production outages stem from preventable software defects and misconfigurations introduced during continuous delivery \cite{dora2024}. Second, when service degradations or node failures occur at runtime, legacy infrastructure controllers such as the Kubernetes Horizontal Pod Autoscaler (HPA) react solely to coarse, lagging resource thresholds (e.g., aggregate CPU or memory consumption). These controllers lack semantic root-cause awareness, often resulting in resource thrashing or inappropriate scaling actions that fail to mitigate non-resource bottlenecks such as thread deadlocks or cascading microservice dependencies. Consequently, industry-wide mean time to recovery (MTTR) commonly spans minutes to hours, exposing enterprise systems to severe service-level agreement (SLA) violations \cite{dora2024,keptn}.

Current DevSecOps practice predominantly bifurcates into two disconnected disciplines. Shift-Left security methodologies seek to identify vulnerabilities and test omissions early in the development lifecycle before code merges \cite{devopshandbook,humblefarley}, utilizing static application security testing (SAST) tools such as Bandit \cite{bandit} and SonarQube \cite{sonarqube}. However, these static analyzers operate in total isolation from runtime cluster topology, lack the ability to synthesize functional corrective patches, and frequently inundate engineering teams with unprioritized warnings. Conversely, Shift-Right operational methodologies deploy runtime observability pipelines and automated rollback mechanisms \cite{accelerate,sre}, often validated through Chaos Engineering fault injection \cite{chaoseng}. Nevertheless, existing runtime controllers remain purely reactive and lack pre-actuation safety verification; executing an automated recovery directive without evaluating downstream queueing stability can destabilize adjacent microservices. Although recent research has explored federated digital twin management (such as SF-DTM \cite{sfdtm}) and large language model (LLM) reasoning for program repair \cite{autocoderover}, no existing platform bridges pre-merge compliance auditing with explainable, safety-verified closed-loop runtime self-healing.

To bridge this operational divide, this paper presents AgentHeal, an autonomous, closed-loop DevSecOps and self-healing platform that synchronizes pre-merge pull-request security auditing with post-deployment runtime remediation over a shared event bus. On the Shift-Left critical path, an event-driven GitHub App intercepts commits and pull requests, analyzes source code against the OWASP Top 10:2021 risk categories using AST structural grammar traversals, checks package dependencies against vulnerability advisory databases, evaluates test-suite coverage gaps, and assigns a standardized compliance score. For non-compliant pull requests, a ReAct-prompted Gemini 2.0 Flash agent autonomously synthesizes a corrective pull request before enforcing a binding CI/CD quality gate. On the Shift-Right critical path, an in-memory digital twin streams four-dimensional cluster telemetry, identifies anomalous states within 2.26~ms using a pre-fitted Isolation Forest, extracts axiomatic root-cause feature attributions via KernelSHAP, arbitrates remediation decisions between a federated Q-learning agent and an LLM reasoning agent, and verifies candidate scaling actions through a SimPy $M/M/c$ discrete-event queueing simulation prior to Kubernetes cluster actuation.

This paper makes three primary contributions:
\begin{enumerate}
\item \textit{Unified Closed-Loop Architecture}: We design and implement AgentHeal, integrating pre-merge OWASP-aligned pull-request compliance auditing with post-deployment Kubernetes self-healing through a shared event-driven topology graph.
\item \textit{Explainable Three-Layer Safety Pipeline}: We introduce an end-to-end safety and arbitration pipeline combining unsupervised anomaly detection, KernelSHAP local feature attribution, dual RL/LLM consensus based on blast-radius minimization, and real-time $M/M/c$ queueing simulation to prevent unsafe actuation.
\item \textit{Comprehensive Empirical Evaluation}: We evaluate AgentHeal on the Google Online Boutique microservice benchmark across four canonical failure modes ($N=15$ repeated trials), demonstrating 2.26~ms anomaly detection latency, 98.3\% detection reliability, and 2.98~s end-to-end MTTR. We further validate the Shift-Left engine across a 50-PR synthetic benchmark (98.5\% precision, 97.5\% recall) and an empirical live GitHub pull-request remediation case study.
\end{enumerate}

\section{Related Work}

A structured taxonomy of related methodologies, standards, and research gaps across autonomous cloud management and DevSecOps compliance is presented in Table~\ref{tab:litreview}.

Early automated incident response relied primarily on rule-based control planes and static operational runbooks. Frameworks such as Keptn \cite{keptn} and Argo Rollouts \cite{argorollouts} automate deployment rollbacks and progressive canary releases but depend strictly on predefined human-authored runbooks, rendering them incapable of adapting to unfamiliar or composite failure signatures. These operational practices were codified industry-wide through Site Reliability Engineering \cite{sre} and validated empirically via controlled fault injection under Chaos Engineering \cite{chaoseng}, while continuous delivery pipelines \cite{humblefarley} and blue-green deployment patterns \cite{fowlerbg} established safe release protocols. However, none of these systems provide autonomous, explainable root-cause diagnosis or closed-loop patch remediation.

To address complex, dynamic cloud workloads, multi-agent reinforcement learning (MARL) approaches demonstrate strong adaptability for cloud resource allocation \cite{marl}, leveraging the theoretical convergence guarantees of temporal-difference Q-learning \cite{qlearning}. Federated learning techniques such as FedAvg \cite{fedavg} facilitate decentralized model training while preserving data privacy. The SF-DTM framework \cite{sfdtm} extended this concept to cloud operations by introducing cosine-similarity-based state matching for federated digital twin management. AgentHeal builds upon SF-DTM, extending its core concepts with a dual-agent RL and LLM consensus mechanism, axiomatic SHAP root-cause attribution, and a real-time discrete-event queueing simulation gate on the critical remediation path.

Anomaly detection in streaming cloud telemetry has been widely explored through unsupervised models such as Isolation Forest \cite{isolationforest} and Local Outlier Factor \cite{lof}, with enterprise AIOps deployments reporting detection latencies in the range of 50--200~ms \cite{aiops}. Our implementation achieves 2.26~ms mean detection latency via pre-fitted in-memory inference on single-node topologies. To make unsupervised anomaly scores actionable, model-agnostic explainability techniques such as KernelSHAP \cite{kernelshap} and LIME \cite{lime} compute local feature attributions; we incorporate KernelSHAP for its rigorous axiomatic properties under game-theoretic Shapley values.

In the software development lifecycle, LLM-based code intelligence platforms such as AutoCodeRover \cite{autocoderover} demonstrate the feasibility of autonomous program repair. However, existing repair tools generate isolated patches without binding CI/CD enforcement or supply-chain compliance verification. AgentHeal integrates Gemini 2.0 Flash \cite{gemini2} within a ReAct reasoning framework \cite{react} to perform targeted auto-remediation bounded by a strict quality gate. Code compliance is measured against the OWASP Top 10:2021 standard \cite{owasp2021}, with ongoing alignment toward the revised OWASP Top 10:2025 taxonomy \cite{owasp2025}. Static linters such as Bandit \cite{bandit} and SonarQube \cite{sonarqube} detect syntactic issues but cannot synthesize fixes or correlate code changes with cluster health. Similarly, supply-chain vulnerability management commonly relies on vulnerability feeds such as the National Vulnerability Database \cite{nvd}, the Open Source Vulnerabilities database \cite{osv}, GitHub Dependabot \cite{dependabot}, and commercial SCA engines such as Snyk \cite{snyk}. AgentHeal's Shift-Left engine combines structural AST parsing with dependency advisory matching to enforce pre-merge quality gates.

Discrete-event simulation for pre-deployment system validation has historical roots in the DEVS formalism \cite{dtsim} and classical queueing theory \cite{queueing}. In AgentHeal, discrete-event simulation via SimPy is adapted into a live, pre-actuation safety gate executed in under 12~ms on the critical path to verify that proposed scaling directives maintain queue stability.

\section{Methodology}

\subsection{End-to-End Self-Healing Architecture Overview}

AgentHeal coordinates two autonomous engines operating over a shared event bus, as illustrated in Fig.~\ref{fig:architecture}. The Shift-Left Engine intercepts GitHub pull request and commit events, executes AST-based security auditing against OWASP Top 10 standards, validates package dependencies, evaluates compliance scores, and invokes a Gemini 2.0 Flash ReAct reasoning engine to synthesize auto-remediation pull requests prior to quality-gate enforcement. The Shift-Right Engine ingests real-time Kubernetes telemetry, detects anomalies using an in-memory Isolation Forest, computes KernelSHAP feature attributions, arbitrates recovery actions between a SimiFed reinforcement learning agent and an LLM reasoning agent, verifies proposed scaling directives via a SimPy $M/M/c$ discrete-event simulation safety gate, and executes actuation commands directly on the cluster. The shared event bus maintains continuous topology and health synchronization across both lifecycles.

\subsection{Shift-Left Engine: PR Intelligence \& Security Compliance}

The Shift-Left engine operates as a GitHub App receiving HMAC-SHA256 authenticated webhook payloads dispatched upon pull request creation and commit pushes. The engine parses source code diffs and dependency declarations through an automated static analysis pipeline that evaluates structural compliance against the ten OWASP Top 10:2021 risk categories:
\begin{itemize}
\item \textit{A01 (Broken Access Control)}: Traverses filesystem resolution subtrees and route definitions to detect unconstrained path concatenation and missing role-based authorization guards.
\item \textit{A02 (Cryptographic Failures)}: Identifies invocations of deprecated cryptographic hashing primitives (e.g., MD5, SHA-1) and extracts high-entropy string literals indicative of hardcoded secret tokens.
\item \textit{A03 (Injection)}: Analyzes abstract syntax tree call nodes to flag unparameterized dynamic string interpolation into database query executions and unescaped shell execution invocations.
\item \textit{A04 (Insecure Design)}: Evaluates data access patterns to intercept unpaginated database queries, unbounded collection retrievals, and missing request rate-limiting decorators.
\item \textit{A05 (Security Misconfiguration)}: Identifies permissive cross-origin resource sharing (CORS) wildcard configurations and active debug mode flags in production service declarations.
\item \textit{A06 (Vulnerable and Outdated Components)}: Conducts software composition analysis (SCA) on project dependency manifests, correlating package version specifications against structured vulnerability advisories \cite{cve}.
\item \textit{A07 (Identification and Authentication Failures)}: Flags disabled cryptographic signature verifications in token processing routines and hardcoded fallback authentication credentials.
\item \textit{A08 (Software and Data Integrity Failures)}: Intercepts unsafe object deserialization mechanisms that expose execution runtimes to arbitrary bytecode execution.
\item \textit{A09 (Security Logging and Monitoring Failures)}: Identifies silent exception handling patterns, suppressed error blocks, and omission of auditable security logging.
\item \textit{A10 (Server-Side Request Forgery)}: Flags outbound HTTP and network socket requests that construct destination URLs from unvalidated user inputs.
\end{itemize}

Every inspected pull request or commit receives a normalized compliance score $S \in [0, 100]$:
\begin{equation}
S = \max\left(0,\ 100 - \sum_{i=1}^{M} w_i \right)
\label{eq:score}
\end{equation}
where $M$ denotes the total number of detected findings and $w_i$ represents the severity penalty weight ($w_{\text{Critical}}=25$, $w_{\text{High}}=15$, $w_{\text{Medium}}=8$, $w_{\text{Low}}=3$). The numeric compliance score maps monotonically to a standardized letter grade:
\begin{equation}
\text{Grade} =
\begin{cases}
A^+ & \text{if } S \geq 95\\
A & \text{if } 90 \leq S < 95\\
B & \text{if } 80 \leq S < 90\\
C & \text{if } 70 \leq S < 80\\
D & \text{if } 60 \leq S < 70\\
F & \text{if } S < 60
\end{cases}
\label{eq:grade}
\end{equation}

In parallel, structural AST comparison determines whether newly introduced public functions have corresponding unit test references:
\begin{equation}
\text{TestGap}(f) = \mathbb{1}[f \notin T_{\text{ast}}]
\label{eq:testgap}
\end{equation}
where $T_{\text{ast}}$ represents the set of functional identifiers referenced within the test suite. If critical findings or test omissions are detected, the GitHub Check Run marks the pull request as non-compliant, preventing merge. Gemini 2.0 Flash then generates an automated remediation branch containing corrective code edits and dependency updates, opening a linked pull request to restore full compliance.

\subsection{Shift-Right Engine: Self-Healing Digital Twin}

The runtime engine synchronizes cluster state by polling Prometheus telemetry every 5.0~s, constructing four-dimensional feature vectors:
\begin{equation}
\mathbf{x}_t = [\text{CPU}_t, \text{RAM}_t, \text{Latency}_t, \text{Rate}_t]^\top \in \mathbb{R}^4
\label{eq:state}
\end{equation}

An in-memory Isolation Forest model ($n=100$ estimators, contamination parameter $\psi=0.05$) evaluates anomaly scores over streaming vectors:
\begin{equation}
s(\mathbf{x}_t, n) = 2^{-\frac{\mathbb{E}[h(\mathbf{x}_t)]}{c(n)}}
\label{eq:isoforest}
\end{equation}
where $h(\mathbf{x}_t)$ is the traversal path length across isolation trees and $c(n)$ is the average path length of unsuccessful searches. An observation is flagged anomalous when $s(\mathbf{x}_t, n) < 0$. Upon anomaly detection, KernelSHAP computes local Shapley values $\phi_i$ across all features:
\begin{equation}
\phi_i(v) = \sum_{S \subseteq F \setminus \{i\}} \frac{|S|!\,(|F|-|S|-1)!}{|F|!}\left[v(S \cup \{i\}) - v(S)\right]
\label{eq:shap}
\end{equation}
providing axiomatic attribution of the root causes driving the deviation.

Remediation decisions are arbitrated across two distinct reasoning layers. First, a SimiFed reinforcement learning agent determines actions via tabular Q-learning over discretized cluster states matched through cosine similarity against historical baseline vectors $\mathbf{b}_k$:
\begin{equation}
k^* = \arg\max_k \frac{\mathbf{x}_t \cdot \mathbf{b}_k}{\|\mathbf{x}_t\|_2 \|\mathbf{b}_k\|_2}
\label{eq:cosine}
\end{equation}
\begin{equation}
Q(s,a) \leftarrow Q(s,a) + \alpha\left[R + \gamma \max_{a'} Q(s',a') - Q(s,a)\right]
\label{eq:qlearn}
\end{equation}
with learning rate $\alpha=0.1$ and discount factor $\gamma=0.95$, over the action space $\mathcal{A} = \{\text{SCALE\_UP}, \text{RESTART\_POD}, \text{PATCH\_LIMITS}, \text{NO\_OP}\}$. Concurrently, a Gemini 2.0 Flash ReAct agent reasons over the KernelSHAP feature attribution summary. If the RL policy and LLM agent propose matching actions, the consensus directive proceeds. If they diverge, an arbitration policy selects the action minimizing operational blast radius:
\begin{equation}
a_{\text{final}} =
\begin{cases}
a^*_{\text{RL}} & \text{if } a^*_{\text{RL}} = a^*_{\text{LLM}}\\
\arg\min\limits_{a \in \{a^*_{\text{RL}}, a^*_{\text{LLM}}\}} \text{BlastRadius}(a) & \text{otherwise}
\end{cases}
\label{eq:consensus}
\end{equation}

Prior to dispatching any command to the Kubernetes API, a discrete-event SimPy queueing simulation models the candidate action under an $M/M/c$ queueing discipline:
\begin{equation}
\rho = \frac{\lambda}{c \mu} \quad (\text{requiring } \rho < 0.95)
\label{eq:rho}
\end{equation}
\begin{equation}
\hat{U}_{\text{post}} = \frac{U_{\text{pre}} \cdot c_{\text{current}}}{c_{\text{new}}} \quad (\text{requiring } \hat{U}_{\text{post}} < 0.80)
\label{eq:upost}
\end{equation}
Actuation proceeds only when both safety conditions are verified, guaranteeing that automated remediation does not trigger cascading instability.

\section{Implementation}

AgentHeal is implemented in Python 3.11 using FastAPI for asynchronous webhook dispatch and telemetry routing. Machine learning components utilize scikit-learn for Isolation Forest anomaly detection and KernelSHAP for local feature attribution. Agentic reasoning incorporates the Google Generative AI SDK interfacing Gemini 2.0 Flash. Discrete-event safety verification is modeled via SimPy 4.1.

The platform is deployed as a containerized microservice on Microsoft Azure Container Apps (East Asia region), provisioned declaratively via Terraform. A multi-stage Docker build produces an optimized runtime image under 400~MB. KEDA HTTP-trigger autoscaling dynamically manages platform replicas.

Validation was conducted against the CNCF Google Online Boutique benchmark \cite{onlineboutique}, a realistic 10-service e-commerce application comprising frontend, cart, checkout, payment, catalog, and currency microservices, hosted on a single-node Kubernetes-in-Docker cluster running on an AMD Ryzen 7 workstation with 16~GB RAM.

\subsection{Comparative Benchmark and System Discussion}

Contextual comparison against reported industry baselines underscores the recovery advantages of AgentHeal's dual-engine architecture. Traditional manual incident response typically requires approximately 45 minutes to detect, triage, and remediate microservice outages \cite{dora2024}. The native Kubernetes Horizontal Pod Autoscaler reacts to sustained resource thresholds within 3--5 minutes \cite{hpa}, but cannot resolve deadlocks or memory leaks that fail to trigger scaling conditions. Rule-based automation control planes such as Keptn achieve MTTRs of 2--4 minutes \cite{keptn}, yet rely entirely on static runbooks. While federated digital twin management frameworks like SF-DTM \cite{sfdtm} report recovery times of approximately 15 seconds, they lack pre-actuation safety verification. In contrast, AgentHeal achieves a mean MTTR of 2.98~s ($\sigma=0.23$~s), representing a $>98\%$ latency reduction relative to threshold autoscalers while ensuring that candidate recovery actions are pre-validated via $M/M/c$ queueing simulation.

Several operational trade-offs and architectural boundaries should guide the interpretation of these findings. First, all Shift-Right experiments were conducted on a single-node Kubernetes development cluster. While in-memory Isolation Forest inference operates in 2.26~ms locally, distributed multi-node topologies subject to network jitter and Prometheus scrape delays may observe higher detection latencies. Second, the four evaluated failure modes represent discrete synthetic injections rather than noisy production traffic; validating generalization against continuous, organic failure traces remains essential. Third, static AST pattern heuristics, while computationally lightweight, do not perform full inter-procedural data-flow or taint tracking; sophisticated obfuscations or non-standard library wrappers may evade pattern detection. Fourth, the compliance scoring weights are heuristic and warrant formal calibration against empirical vulnerability risk datasets. \enlargethispage{2\baselineskip}
Finally, the non-deterministic nature of generative LLMs requires strict execution timeouts and deterministic RL fallback policies on the critical remediation path.

\section{Conclusion}

This paper presented AgentHeal, an autonomous DevSecOps and self-healing platform that synchronizes pre-merge pull-request compliance auditing with post-deployment runtime remediation. Across repeated trials on the Google Online Boutique microservice benchmark, AgentHeal demonstrated 2.26~ms anomaly detection latency, 98.3\% detection reliability, and an average end-to-end recovery time of 2.98~s, reducing MTTR by over 98\% compared to reactive autoscalers. Concurrently, the Shift-Left engine attained 98.5\% precision across 50 pull requests and autonomously remediated 14 OWASP defect categories on a live production repository.

Future work will expand evaluation to multi-node managed clusters (AKS/GKE), integrate live vulnerability intelligence feeds such as NVD and OSV, incorporate dynamic taint analysis, and map the compliance auditing engine to the revised OWASP Top 10:2025 taxonomy.
