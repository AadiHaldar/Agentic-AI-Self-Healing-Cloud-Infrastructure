\begin{abstract}
Kubernetes-based microservice deployments today suffer from two closely linked problems that existing tools handle in isolation. Code vulnerabilities slip through during development because static analyzers have no awareness of what is actually happening in production. And when something breaks at runtime, autoscalers react to surface-level CPU numbers without understanding the real cause, which often means they make things worse. We built AgentHeal to tackle both problems together through a single closed-loop system. Before code is merged, a GitHub App scans pull requests for OWASP Top 10:2021 violations using AST-level analysis, checks dependencies for known CVEs, scores each PR for compliance, and uses a Gemini 2.0 Flash reasoning agent to automatically generate a fix branch when issues are found. After deployment, a live digital twin tracks cluster telemetry, flags anomalies using an Isolation Forest model in 2.26~ms, explains which metric is driving the problem via KernelSHAP, and runs two agents in parallel: a SimiFed reinforcement learning agent and an LLM agent. Before anything is executed on the cluster, the proposed action is validated through a SimPy $M/M/c$ discrete-event simulation to ensure it will not trigger a cascade failure. We tested AgentHeal against the Google Online Boutique benchmark across four fault injection scenarios with $N=15$ trials each. Mean detection latency was 2.26~ms ($\sigma=0.37$~ms) with a 98.3\% detection rate, and end-to-end recovery averaged 2.98~s ($\sigma=0.23$~s), a greater than 98\% improvement over threshold-based autoscalers. The static analysis pipeline achieved 98.5\% precision and 97.5\% recall over 50 synthetic pull requests, and fully remediated 14 injected vulnerabilities across all OWASP categories in a live GitHub pull request test.
\end{abstract}

\section{Introduction}

Teams running microservice applications on Kubernetes face two problems that compound each other in practice. The first is that code changes introduce security flaws and misconfigurations that slip into production undetected; the 2024 State of DevOps report puts over 60\% of unplanned outages down to preventable defects introduced during development \cite{dora2024}. The second is that when something does break in production, the standard response is either a human on-call engineer who may take 30 to 60 minutes to act, or the Kubernetes HPA which blindly scales replicas based on aggregate CPU without any understanding of what is actually wrong. Neither is adequate when the failure is a deadlock, a memory leak, or a cascading dependency collapse \cite{dora2024,keptn}.

The two disciplines that are supposed to handle these problems, Shift-Left static analysis and Shift-Right runtime operations, have historically had nothing to do with each other. Tools like Bandit \cite{bandit} and SonarQube \cite{sonarqube} scan code during CI/CD but have no idea what the cluster looks like at runtime and cannot write fixes. Runtime observability and chaos engineering \cite{chaoseng,sre} tell you when something is broken but offer no pre-merge prevention and no root-cause attribution beyond metric thresholds. Recent work on federated digital twin management \cite{sfdtm} and LLM-driven program repair \cite{autocoderover} has pushed each side forward, but nothing has connected them end-to-end with a safety verification step before acting.

We built AgentHeal specifically to close this gap. On the pre-merge side, a GitHub App intercepts every pull request, scans code structure against all ten OWASP Top 10:2021 categories, checks dependency files for known CVEs, and scores the result numerically. When a PR fails, a Gemini 2.0 Flash agent generates a corrective patch and opens a linked fix branch. The CI/CD quality gate blocks the merge until the score recovers. On the runtime side, a digital twin polls Prometheus telemetry every five seconds, runs the snapshot through an in-memory Isolation Forest (mean detection time 2.26~ms), identifies which metric is responsible via KernelSHAP, and sends the attribution to two agents running in parallel: a tabular SimiFed Q-learning agent and a Gemini LLM ReAct agent. Before anything touches the live cluster, the proposed action is simulated in SimPy using an $M/M/c$ queueing model to confirm it will not cause a brownout.

This paper makes three contributions:
\begin{enumerate}
\item \textit{Unified Closed-Loop Architecture}: AgentHeal connects pre-merge OWASP compliance auditing with post-deployment Kubernetes self-healing through a shared event bus and a common topology graph, a combination that to our knowledge has not been implemented before.
\item \textit{Explainable Safety-Gated Remediation Pipeline}: We combine Isolation Forest anomaly detection, KernelSHAP attribution, dual RL/LLM consensus with blast-radius arbitration, and real-time $M/M/c$ simulation into a single non-bypassable actuation path.
\item \textit{Empirical Evaluation}: We report results across four synthetic fault scenarios ($N=15$ trials each) on Google Online Boutique, a 50-PR static analysis benchmark, and a live end-to-end case study on a public GitHub repository.
\end{enumerate}

\section{Related Work}

Table~\ref{tab:litreview} surveys existing approaches across autonomous cloud management and DevSecOps compliance and identifies where each falls short.

The first generation of automated incident response was essentially runbook automation. Keptn \cite{keptn} and Argo Rollouts \cite{argorollouts} can trigger rollbacks and canary promotions automatically, but only according to rules a human wrote in advance. If the failure pattern is new, the runbook does not apply. This limitation is well documented in the SRE literature \cite{sre} and underscores why chaos engineering \cite{chaoseng} is used primarily for validating expected failure modes rather than discovering novel ones.

On the machine learning side, multi-agent reinforcement learning has shown good results for cloud resource allocation \cite{marl}, and the convergence properties of Q-learning \cite{qlearning} are well established. FedAvg \cite{fedavg} introduced federated model training across distributed nodes without sharing raw data. The SF-DTM framework \cite{sfdtm} applied these ideas to cloud operations, using cosine similarity to match live cluster states against baseline vectors in a federated digital twin. We take SF-DTM as our starting point and extend it with a second LLM reasoning agent, KernelSHAP-based attribution, and a SimPy simulation safety gate before any cluster action is taken.

For anomaly detection, Isolation Forest \cite{isolationforest} and LOF \cite{lof} are the standard choices in the AIOps literature. Production deployments typically report latencies of 50 to 200~ms \cite{aiops}; we achieve 2.26~ms by keeping the trained model in memory and operating on single-node topologies. KernelSHAP \cite{kernelshap} is our choice over LIME \cite{lime} because its Shapley value foundation provides efficiency, symmetry, and additivity guarantees that make attributions stable and comparable across runs.

For automated code repair, AutoCodeRover \cite{autocoderover} shows that LLMs can locate and patch real bugs, but it operates outside any CI/CD pipeline. AgentHeal uses Gemini 2.0 Flash \cite{gemini2} in a ReAct loop \cite{react} to generate patches that are tested by the existing CI suite before the fix PR is opened. The compliance scoring uses OWASP Top 10:2021 \cite{owasp2021} as its taxonomy, with OWASP Top 10:2025 \cite{owasp2025} noted for future alignment. Dependency checking is currently handled via a curated advisory list rather than live feeds like NVD \cite{nvd}, OSV \cite{osv}, or Dependabot \cite{dependabot}, which is an acknowledged limitation. Finally, discrete-event simulation has deep roots in DEVS formalism \cite{dtsim} and queueing theory \cite{queueing}; our contribution is adapting SimPy into a sub-12~ms on-path gate rather than an offline planning tool.

\section{Methodology}

\subsection{End-to-End Self-Healing Architecture Overview}

The overall system is shown in Fig.~\ref{fig:architecture}. Two engines run continuously and share a common event bus and topology state. The Shift-Left Engine wakes up on every GitHub pull request or push event, checks the diff against OWASP Top 10:2021 rules using AST traversal, validates dependency versions, computes a compliance score, and if the score is below threshold, calls Gemini 2.0 Flash to generate a corrective patch PR. The Shift-Right Engine runs a background loop: every five seconds it polls Prometheus, updates the digital twin graph, feeds the new telemetry snapshot to the Isolation Forest, and if an anomaly is flagged, passes the SHAP attribution to both the SimiFed RL agent and the LLM agent in parallel. The two agents propose actions independently; if they agree, the consensus directive goes straight to the SimPy safety gate. If they disagree, the arbiter picks the lower-blast-radius option. The SimPy gate runs the proposed action through an $M/M/c$ queue simulation and only permits cluster actuation if the projected post-action utilization is below 80\% and queue load $\rho < 0.95$.

\subsection{Shift-Left Engine: PR Intelligence \& Security Compliance}

The Shift-Left engine is deployed as a GitHub App. When a developer opens or updates a pull request, GitHub sends an HMAC-SHA256 authenticated webhook payload to our service endpoint. The engine then parses the diff and dependency files through a static analysis pipeline covering all ten OWASP Top 10:2021 categories:
\begin{itemize}
\item \textit{A01 (Broken Access Control)}: Traverses filesystem resolution subtrees and route definitions to detect unconstrained path concatenation and missing role-based authorization guards.
\item \textit{A02 (Cryptographic Failures)}: Identifies invocations of deprecated cryptographic hashing primitives (e.g., MD5, SHA-1) and extracts high-entropy string literals indicative of hardcoded secret tokens.
\item \textit{A03 (Injection)}: Analyzes abstract syntax tree call nodes to flag unparameterized dynamic string interpolation into database query executions and unescaped shell execution invocations.
\item \textit{A04 (Insecure Design)}: Evaluates data access patterns to intercept unpaginated database queries, unbounded collection retrievals, and missing request rate-limiting decorators.
\item \textit{A05 (Security Misconfiguration)}: Identifies permissive cross-origin resource sharing (CORS) wildcard configurations and active debug mode flags in production service declarations.
\item \textit{A06 (Vulnerable and Outdated Components)}: Conducts software composition analysis (SCA) on project dependency manifests, correlating package version specifications against structured vulnerability advisories \cite{cve}.
\item \textit{A07 (Identification and Authentication Failures)}: Flags disabled cryptographic signature verifications in token processing routines and hardcoded fallback authentication credentials.
\item \textit{A08 (Software and Data Integrity Failures)}: Intercepts unsafe object deserialization mechanisms that expose execution runtimes to arbitrary bytecode execution.
\item \textit{A09 (Security Logging and Monitoring Failures)}: Identifies silent exception handling patterns, suppressed error blocks, and omission of auditable security logging.
\item \textit{A10 (Server-Side Request Forgery)}: Flags outbound HTTP and network socket requests that construct destination URLs from unvalidated user inputs.
\end{itemize}

Every inspected pull request or commit receives a normalized compliance score $S \in [0, 100]$:
\begin{equation}
S = \max\left(0,\ 100 - \sum_{i=1}^{M} w_i \right)
\label{eq:score}
\end{equation}
where $M$ is the number of findings and $w_i$ is the severity weight assigned to finding $i$ ($w_{\text{Critical}}=25$, $w_{\text{High}}=15$, $w_{\text{Medium}}=8$, $w_{\text{Low}}=3$). The numeric score maps to a letter grade:
\begin{equation}
\text{Grade} =
\begin{cases}
A^+ & \text{if } S \geq 95\\
A & \text{if } 90 \leq S < 95\\
B & \text{if } 80 \leq S < 90\\
C & \text{if } 70 \leq S < 80\\
D & \text{if } 60 \leq S < 70\\
F & \text{if } S < 60
\end{cases}
\label{eq:grade}
\end{equation}

The engine also checks whether newly introduced public functions are covered by the test suite using AST symbol matching:
\begin{equation}
\text{TestGap}(f) = \mathbb{1}[f \notin T_{\text{ast}}]
\label{eq:testgap}
\end{equation}
where $T_{\text{ast}}$ is the set of function names referenced in the tests directory. A PR that scores below 60 or has uncovered public functions triggers the GitHub Check Run to block the merge. Gemini 2.0 Flash then constructs a remediation branch and opens a linked PR that addresses the identified issues.

\subsection{Shift-Right Engine: Self-Healing Digital Twin}

Every five seconds the runtime engine polls Prometheus and builds a four-dimensional feature vector for each pod:
\begin{equation}
\mathbf{x}_t = [\text{CPU}_t, \text{RAM}_t, \text{Latency}_t, \text{Rate}_t]^\top \in \mathbb{R}^4
\label{eq:state}
\end{equation}

These vectors are scored by a pre-fitted Isolation Forest (100 estimators, contamination $\psi=0.05$):
\begin{equation}
s(\mathbf{x}_t, n) = 2^{-\frac{\mathbb{E}[h(\mathbf{x}_t)]}{c(n)}}
\label{eq:isoforest}
\end{equation}
where $h(\mathbf{x}_t)$ is the mean path length across isolation trees and $c(n)$ is the expected path length under random partitioning. A negative score flags an anomaly. At that point KernelSHAP runs to figure out which feature is responsible:
\begin{equation}
\phi_i(v) = \sum_{S \subseteq F \setminus \{i\}} \frac{|S|!\,(|F|-|S|-1)!}{|F|!}\left[v(S \cup \{i\}) - v(S)\right]
\label{eq:shap}
\end{equation}
The attribution vector $\phi$ tells both agents which metric to act on, which avoids remediation actions that would address the wrong dimension.

The RL agent uses cosine similarity to find the historical baseline closest to the current state and then selects an action via Q-learning:
\begin{equation}
k^* = \arg\max_k \frac{\mathbf{x}_t \cdot \mathbf{b}_k}{\|\mathbf{x}_t\|_2 \|\mathbf{b}_k\|_2}
\label{eq:cosine}
\end{equation}
\begin{equation}
Q(s,a) \leftarrow Q(s,a) + \alpha\left[R + \gamma \max_{a'} Q(s',a') - Q(s,a)\right]
\label{eq:qlearn}
\end{equation}
with $\alpha=0.1$, $\gamma=0.95$, and action space $\mathcal{A} = \{\text{SCALE\_UP}, \text{RESTART\_POD}, \text{PATCH\_LIMITS}, \text{NO\_OP}\}$. The LLM agent receives the SHAP summary and reasons independently. When both agents agree, the action proceeds. When they disagree:
\begin{equation}
a_{\text{final}} =
\begin{cases}
a^*_{\text{RL}} & \text{if } a^*_{\text{RL}} = a^*_{\text{LLM}}\\
\arg\min\limits_{a \in \{a^*_{\text{RL}}, a^*_{\text{LLM}}\}} \text{BlastRadius}(a) & \text{otherwise}
\end{cases}
\label{eq:consensus}
\end{equation}

The SimPy safety gate runs the chosen action through an $M/M/c$ simulation before the cluster is touched:
\begin{equation}
\rho = \frac{\lambda}{c \mu} \quad (\text{requiring } \rho < 0.95)
\label{eq:rho}
\end{equation}
\begin{equation}
\hat{U}_{\text{post}} = \frac{U_{\text{pre}} \cdot c_{\text{current}}}{c_{\text{new}}} \quad (\text{requiring } \hat{U}_{\text{post}} < 0.80)
\label{eq:upost}
\end{equation}
If either bound is violated, actuation is blocked and the next least-disruptive action is tried instead.

\section{Implementation}

The platform is written in Python 3.11 with FastAPI handling asynchronous webhook dispatch and telemetry routing. scikit-learn provides the Isolation Forest, and the SHAP library handles KernelSHAP attribution. Gemini 2.0 Flash is accessed via the Google Generative AI SDK. SimPy 4.1 runs the discrete-event safety simulation. The system is packaged using a multi-stage Docker build that keeps the final runtime image under 400~MB, and deployed on Microsoft Azure Container Apps (East Asia region) with Terraform-managed infrastructure and KEDA HTTP autoscaling.

All experiments used the CNCF Google Online Boutique benchmark \cite{onlineboutique}, a 10-service e-commerce application running on a kind single-node Kubernetes cluster on an AMD Ryzen 7 workstation with 16~GB RAM.

\subsection{Comparative Benchmark and System Discussion}

To put these numbers in context: typical human on-call MTTR for microservice outages is around 45 minutes \cite{dora2024}. The Kubernetes HPA responds in 3 to 5 minutes \cite{hpa} but cannot handle deadlocks or memory leaks. Keptn handles those in 2 to 4 minutes \cite{keptn} but only for pre-scripted scenarios. SF-DTM brings it down to roughly 15 seconds \cite{sfdtm} but has no actuation safety check. AgentHeal reaches 2.98~s with a mandatory simulation gate before every cluster change.

There are honest limitations worth noting. All Shift-Right experiments ran on a single-node development cluster; multi-node deployments with Prometheus scrape delays will likely see higher MTTD. The four fault modes are synthetic and discrete rather than messy organic production traffic. AST pattern matching does not do full inter-procedural taint analysis, so sophisticated obfuscations may evade it. The compliance scoring weights were set heuristically and have not been calibrated against real-world vulnerability severity data. \enlargethispage{2\baselineskip}
And LLM non-determinism means the system needs hard timeout enforcement and always-available RL fallback policies on the remediation path.

\section{Conclusion}

AgentHeal addresses a real gap: no existing tool simultaneously prevents security regressions before merge and self-heals production outages at sub-second speed. Across 60 trials on Google Online Boutique, we measured a mean MTTD of 2.26~ms, a 98.3\% detection rate, and a mean MTTR of 2.98~s, more than 98\% faster than threshold autoscalers. The Shift-Left engine hit 98.5\% precision on 50 synthetic PRs and autonomously patched 14 OWASP violations in a live GitHub repository without any human intervention.

The next steps are running on AKS or GKE multi-node clusters, integrating live CVE feeds from NVD and OSV, adding taint analysis for the AST scanner, and updating the compliance rules to OWASP Top 10:2025.
