\begin{abstract}
Modern Kubernetes-based microservice architectures face dual reliability challenges: pre-merge code defects and slow runtime incident recovery. Current DevSecOps practice predominantly relies on either static analysis tools that cannot generate fixes or correlate findings with runtime impact, or threshold-based autoscalers that react without explainability or root-cause understanding. To address these limitations, this paper presents AgentHeal, a closed-loop platform combining (i) a Shift-Left Engine that audits GitHub commits and Pull Requests via an OWASP Top 10:2021-aligned AST/regex rule set, supply-chain CVE matching, and Gemini 2.0 Flash ReAct auto-remediation, and (ii) a Shift-Right Engine that streams 4-dimensional telemetry vectors, detects anomalies with Isolation Forest, computes KernelSHAP feature attribution, arbitrates between a SimiFed Federated Reinforcement Learning agent and a Gemini ReAct LLM, and validates remediation actions through a SimPy M/M/c queuing safety simulation before executing Kubernetes commands. We evaluate the Shift-Right engine across four canonical failure scenarios on the Google Online Boutique benchmark, each repeated $N=15$ trials: Isolation Forest achieves a mean detection latency of 2.26~ms ($\sigma=0.37$~ms) with a per-scenario detection rate of $\geq 93\%$, and mean end-to-end remediation time ranges from 2.66~s ($\sigma=0.18$~s) to 3.25~s ($\sigma=0.30$~s). The Shift-Left engine achieves 98.5\% precision and 97.5\% recall on a 50-PR synthetic evaluation set. In addition, we present a single illustrative case study on a live public PR pair, in which the engine detected 14 injected OWASP-category flaws and produced an auto-fix PR restoring full compliance; this case study is a qualitative demonstration ($N=1$) and is not part of the quantitative evaluation above. These results are consistent and repeatable on a single-node Kubernetes-in-Docker cluster; broader production generalizability remains an open question requiring larger-scale evaluation.
\end{abstract}

\section{Introduction}

Distributed cloud-native applications deployed on Kubernetes-orchestrated microservice architectures suffer from two primary reliability challenges. First, insufficiently reviewed Pull Requests (PRs) and unvetted commits allow vulnerable, untested code to reach production; the 2024 DORA report estimates that 62\% of outages are caused by preventable software defects \cite{dora2024}. Second, even with Kubernetes-native autoscaling mechanisms (e.g., HPA), the mean time to recovery (MTTR) from unplanned incidents in microservice environments commonly ranges from minutes to hours, depending on incident complexity and on-call triage latency \cite{dora2024,keptn}.

Two complementary engineering philosophies address these operational layers. Shift-Left Testing \& Security \cite{devopshandbook} moves code quality, OWASP-aligned vulnerability detection, and test-coverage validation earlier in the development lifecycle---before code merges---to catch defects while they are cheapest to fix, a discipline further formalized through continuous-delivery pipelines \cite{humblefarley} and traffic-switching release patterns such as blue-green deployment \cite{fowlerbg}. Shift-Right Monitoring \& Remediation \cite{accelerate} deploys intelligent runtime observability and auto-remediation systems that detect and resolve production incidents autonomously, extending operational disciplines established by Site Reliability Engineering \cite{sre} and empirically validated through controlled fault injection under Chaos Engineering \cite{chaoseng}.

Existing tools address each pillar in isolation. Static analysis tools such as Bandit \cite{bandit} and SonarQube \cite{sonarqube} perform pre-merge analysis but cannot generate fixes, compute compliance scores, or correlate findings with runtime impact. Kubernetes HPA \cite{hpa} reacts to coarse CPU thresholds without explainability, root-cause understanding, or pre-execution safety guarantees.

This paper makes four primary contributions. First, a dual-engine agentic architecture (AgentHeal) integrates pre-merge OWASP Top 10:2021-aligned Shift-Left PR intelligence with post-deploy Shift-Right Kubernetes self-healing into a unified closed-loop platform. Second, an OWASP Top 10:2021 Compliance \& Supply Chain Engine provides quantitative compliance scoring (0--100, Letter Grades A+ to F), AST-level vulnerability detection, and CVE advisory matching, motivated by the gap between static curated lists and live feeds such as the National Vulnerability Database \cite{nvd} and the Open Source Vulnerabilities database \cite{osv}. Third, a three-layer safety architecture combining deterministic SAST/OWASP auditing, dual-agent RL+LLM consensus, and SimPy M/M/c pre-execution digital-twin simulation prevents unsafe actuation before any Kubernetes command executes. Finally, we present repeated-trial empirical evaluation of the Shift-Right engine ($N=15$ trials per scenario) and a 50-PR synthetic evaluation of the Shift-Left engine, both on the CNCF Google Online Boutique benchmark, supplemented by a single illustrative live-PR case study demonstrating end-to-end detection and auto-remediation on a real GitHub PR pair; the live-PR case study is reported separately from the repeated-trial results and should not be read as evidence of comparable statistical rigor.

\section{Related Work}

A comprehensive summary of recent methodologies, standards, and research gaps relevant to autonomous cloud self-healing and DevSecOps compliance auditing is presented in Table~\ref{tab:litreview}.

Early automated incident response relied primarily on rule-based control planes and human-authored runbooks. Keptn \cite{keptn} and Argo Rollouts \cite{argorollouts} automate deployment rollbacks and progressive delivery but require manual runbook authoring and cannot adapt to novel failure signatures. These practices were formalized industry-wide through Site Reliability Engineering \cite{sre} and validated empirically via controlled fault injection under Chaos Engineering \cite{chaoseng}, while continuous-delivery pipelines \cite{humblefarley} and blue-green deployment patterns \cite{fowlerbg} codified safe, human-supervised release practices. None of these approaches, however, incorporate autonomous, explainable root-cause remediation.

To adapt to dynamic and previously unseen failure modes, multi-agent reinforcement learning approaches \cite{marl} demonstrate superior adaptability for cloud resource management, building on the foundational convergence guarantees of tabular Q-learning \cite{qlearning}. Federated learning techniques such as FedAvg \cite{fedavg} enable privacy-preserving distributed model training, a principle extended by the SF-DTM framework \cite{sfdtm}, which introduces cosine-similarity-based state matching for federated digital twin management. Our work builds directly on SF-DTM, extending it with a multi-agent RL+LLM consensus layer and a SimPy queuing safety gate on the critical remediation path.

Anomaly detection in cloud telemetry has been extensively studied through unsupervised methods such as Isolation Forest \cite{isolationforest} and Local Outlier Factor \cite{lof}, with AIOps deployments reporting detection latencies of 50--200~ms \cite{aiops}. Our streaming implementation achieves 2.26~ms mean detection latency through pre-fitted in-memory inference; we note this is measured on a local single-node cluster and is not directly comparable to distributed production deployments. To render anomaly decisions interpretable, model-agnostic explainability techniques such as KernelSHAP \cite{kernelshap} and LIME \cite{lime} provide local feature attribution; we adopt KernelSHAP for its axiomatic consistency under the Shapley value framework.

LLM-driven code review, exemplified by AutoCodeRover \cite{autocoderover}, demonstrates the potential of large models for autonomous program repair, but such systems typically produce narrative summaries or isolated patches without binding CI/CD enforcement or supply-chain verification. AgentHeal integrates Gemini 2.0 Flash \cite{gemini2} as a ReAct \cite{react} reasoning agent within a binding quality-gate pipeline whose rule set is aligned to the OWASP Top 10:2021 \cite{owasp2021}; we note OWASP has since published a revised Top 10:2025 taxonomy \cite{owasp2025} to which the current rule set has not yet been remapped.

Static analysis tools such as Bandit \cite{bandit} and SonarQube \cite{sonarqube} perform pre-merge analysis but cannot generate fixes, compute compliance scores, or correlate findings with runtime impact. Supply-chain vulnerability matching is more commonly addressed through live feeds such as the National Vulnerability Database \cite{nvd}, the Open Source Vulnerabilities database \cite{osv}, GitHub Dependabot \cite{dependabot}, and commercial software-composition-analysis tools such as Snyk \cite{snyk}; by contrast, AgentHeal's current A06 rule matches only against a small, manually curated CVE list, a narrower and less current source than these live feeds. Kubernetes HPA \cite{hpa} and GitOps controllers such as Argo CD \cite{argocd} automate scaling and deployment reconciliation respectively, but react to coarse thresholds without explainability or pre-execution safety guarantees. Telemetry in AgentHeal is collected via Prometheus \cite{prometheus}, the de facto standard for Kubernetes-native metrics collection.

Discrete-event simulation for pre-deployment validation has been applied in manufacturing and network engineering through the DEVS formalism \cite{dtsim} and classical queuing theory \cite{queueing}. To our knowledge, this work is the first to deploy SimPy M/M/c queuing simulation as a real-time Kubernetes actuation safety gate, executed in $<15$~ms on the remediation critical path.

\section{Methodology}

\subsection{End-to-End Self-Healing Architecture Overview}

AgentHeal consists of two synchronized engines operating on a shared event bus, as illustrated in Fig.~\ref{fig:architecture}. The Shift-Left Engine intercepts GitHub PR and push events, performs OWASP-aligned AST and CVE analysis, invokes a Gemini ReAct fix engine for non-compliant code, and enforces a binding quality gate. The Shift-Right Engine streams live Kubernetes telemetry, detects anomalies with Isolation Forest, computes KernelSHAP attributions, arbitrates a remediation action between a federated RL agent and a Gemini ReAct LLM agent, validates the proposed action through a SimPy discrete-event safety simulation, and only then dispatches the Kubernetes actuation command.

\subsection{Shift-Left Engine: PR Intelligence \& Security Compliance}

The Shift-Left engine is implemented as a GitHub App receiving HMAC-SHA256-authenticated webhook payloads at an Azure Container Apps HTTPS endpoint. It processes both \texttt{pull\_request} and \texttt{push} events through the multi-stage verification pipeline shown in Fig.~\ref{fig:architecture}.

The engine evaluates code against the ten OWASP Top 10:2021 risk categories via AST pattern extraction and regex heuristics. These are pattern-matching heuristics tuned to specific call signatures and identifier names observed in our test corpus rather than general data-flow or taint analysis; a semantically equivalent but differently-named or differently-structured instance of a given flaw may not currently be detected. A01 Broken Access Control is flagged through untrusted path concatenation into \texttt{os.path.join()} without sanitization. A02 Cryptographic Failures are flagged through \texttt{hashlib.md5()}/\texttt{sha1()} calls and high-entropy hardcoded string literals resembling API keys or secrets. A03 Injection is identified via f-string/format-string interpolation directly into SQL execution calls, and via \texttt{subprocess.Popen(..., shell=True)}. A04 Insecure Design is detected through calls to a small set of named helper functions associated with unbounded record retrieval in our test corpus (e.g., functions named \texttt{fetch\_unbounded}, \texttt{load\_all\_records}, \texttt{query\_all}); this remains a name-based heuristic rather than a general unbounded-query detector. A05 Security Misconfiguration is caught via static boolean assignment to variables named \texttt{DEBUG}/\texttt{DEBUG\_MODE}, and wildcard CORS configuration (\texttt{allow\_origins=["*"]}). A06 Vulnerable and Outdated Components are identified by parsing \texttt{requirements.txt} and matching pinned versions against a small, manually curated CVE list \cite{cve} (e.g., \texttt{pyyaml==5.3} $\rightarrow$ CVE-2020-14343; \texttt{requests==2.28.0} $\rightarrow$ CVE-2023-32681); unlike live feeds such as NVD \cite{nvd} or OSV \cite{osv}, this coverage is limited to the entries in the curated list. A07 Identification \& Auth Failures are flagged through hardcoded credential-like literals and \texttt{jwt.decode(..., verify=False)}. A08 Software \& Data Integrity Failures are identified via \texttt{pickle.loads()} and \texttt{yaml.load()} without \texttt{SafeLoader}. A09 Security Logging \& Monitoring Failures are detected through exception handlers containing only \texttt{pass} or \texttt{continue}. Finally, A10 Server-Side Request Forgery is flagged via outbound requests (\texttt{requests.get}, \texttt{urllib.request.urlopen}) to a dynamic, unvalidated URL argument.

Every inspected commit or PR receives a compliance score $S \in [0,100]$:
\begin{equation}
S = \max\left(0,\ 100 - \sum_{i=1}^{M} w_i \right)
\label{eq:score}
\end{equation}
where $M$ is the number of detected findings and $w_i$ is a severity penalty weight ($w_{\text{Critical}}=25$, $w_{\text{High}}=15$, $w_{\text{Medium}}=8$, $w_{\text{Low}}=3$). These weights are currently set heuristically and have not been empirically calibrated or validated against expert severity judgments; the resulting letter grade should be read as an illustrative summary rather than a validated risk metric. The score maps to a letter grade:
\begin{equation}
\text{Grade} =
\begin{cases}
A^+ & \text{if } S \geq 95\\
A & \text{if } 90 \leq S < 95\\
B & \text{if } 80 \leq S < 90\\
C & \text{if } 70 \leq S < 80\\
D & \text{if } 60 \leq S < 70\\
F & \text{if } S < 60
\end{cases}
\label{eq:grade}
\end{equation}

Parsing Python ASTs additionally identifies newly introduced public functions lacking a corresponding test reference:
\begin{equation}
\text{TestGap}(f) = \mathbb{1}[f \notin T_{\text{ast}}]
\label{eq:testgap}
\end{equation}
where $T_{\text{ast}}$ is the set of function symbols referenced in test files. An asynchronous TLS SMTP dispatcher formats a vulnerability scorecard (composite grade, categorized flaw inventory, auto-fix PR link) delivered to repository owners, with fallback to an in-memory outbox cache if SMTP connectivity is unavailable. A GitHub Check Run sets commit status to \texttt{action\_required} (blocking merge) or \texttt{success}; for non-compliant PRs, Gemini 2.0 Flash constructs a remediation branch (\texttt{agentheal/fix-pr-*}) and opens an auto-fix PR.

\subsection{Shift-Right Engine: Self-Healing Digital Twin}


The \texttt{StateSynchronizer} polls Prometheus \cite{prometheus} metrics every 5.0~s, assembling 4-dimensional state vectors:
\begin{equation}
\vec{X}_t = [\text{CPU}_t, \text{RAM}_t, \text{Latency}_t, \text{Rate}_t] \in \mathbb{R}^4
\label{eq:state}
\end{equation}

A pre-fitted Isolation Forest \cite{isolationforest} ($n=100$ estimators, contamination $\psi=0.05$) computes anomaly scores in-memory:
\begin{equation}
s(\vec{X}_t, n) = 2^{-\frac{E[h(\vec{X}_t)]}{c(n)}}
\label{eq:isoforest}
\end{equation}
where $h(\vec{X}_t)$ is the path length for sample $\vec{X}_t$ and $c(n)$ is the expected path-length normalization. A sample is flagged anomalous when $s < 0$. For each anomalous observation, KernelSHAP \cite{kernelshap} computes Shapley values $\phi_i$ for each feature:
\begin{equation}
\phi_i(v) = \sum_{S \subseteq F \setminus \{i\}} \frac{|S|!\,(|F|-|S|-1)!}{|F|!}\left[v(S \cup \{i\}) - v(S)\right]
\label{eq:shap}
\end{equation}

The SimiFed RL agent selects actions via tabular Q-learning \cite{qlearning} over cosine-similarity-discretized states:
\begin{equation}
k^* = \arg\max_k \frac{\vec{X}_t \cdot \vec{B}_k}{\|\vec{X}_t\|_2 \cdot \|\vec{B}_k\|_2}
\label{eq:cosine}
\end{equation}
\begin{equation}
Q(s,a) \leftarrow Q(s,a) + \alpha\left[R + \gamma \max_{a'} Q(s',a') - Q(s,a)\right]
\label{eq:qlearn}
\end{equation}
with $\alpha=0.1$, $\gamma=0.95$. Action space $A = \{\text{SCALE\_UP}, \text{RESTART\_POD}, \text{PATCH\_LIMITS}, \text{NO\_OP}\}$. Concurrently, Gemini 2.0 Flash \cite{gemini2} reasons over the KernelSHAP attribution summary following the ReAct paradigm \cite{react} (Thought $\rightarrow$ Action $\rightarrow$ Observation). Being a proprietary, non-deterministic model, LLM latency and outputs vary across invocations; run-to-run variance is reported in Table~\ref{tab:agentlatency}. If the RL and LLM agents agree, the consensus action proceeds; if they diverge, the lower-blast-radius action is selected:
\begin{equation}
a_{\text{final}} =
\begin{cases}
a^*_{\text{RL}} & \text{if } a^*_{\text{RL}} = a^*_{\text{LLM}}\\
\arg\min\limits_{a \in \{a^*_{\text{RL}}, a^*_{\text{LLM}}\}} \text{BlastRadius}(a) & \text{otherwise}
\end{cases}
\label{eq:consensus}
\end{equation}

Before executing any Kubernetes command, a SimPy discrete-event simulation \cite{queueing} verifies proposed SCALE\_UP actions:
\begin{equation}
\rho = \frac{\lambda}{c \cdot \mu} \quad (\text{must satisfy } \rho < 0.95)
\label{eq:rho}
\end{equation}
\begin{equation}
\hat{U}_{\text{post}} = \frac{U_{\text{pre}} \cdot c_{\text{current}}}{c_{\text{new}}} \quad (\text{must satisfy } \hat{U}_{\text{post}} < 0.80)
\label{eq:upost}
\end{equation}
The action is marked SAFE\_TO\_EXECUTE only if both conditions hold.

\section{Implementation}

Stack: FastAPI 0.115 (Python 3.11); scikit-learn 1.4 (Isolation Forest, KernelSHAP); Google Generative AI SDK (Gemini 2.0 Flash); SimPy 4.1; Bandit 1.7; Detect-Secrets 1.4; Ruff 0.4; SMTP/TLS email pipeline; Prometheus \cite{prometheus} for telemetry collection.

Deployment: Microsoft Azure Container Apps (East Asia region), provisioned via Terraform (\texttt{azurerm} v3.90). A multi-stage Docker build (\texttt{node:20-alpine} frontend, \texttt{python:3.11-slim} backend) produces a $<400$~MB image. KEDA HTTP-trigger autoscaling scales replicas from zero on demand.

Benchmark: The Google Online Boutique \cite{onlineboutique} 10-service e-commerce application, deployed on a \texttt{kind} (Kubernetes-in-Docker) single-node cluster (AMD Ryzen 7, 16~GB RAM). This is a local development cluster, not a production multi-node/multi-zone deployment; results should be interpreted accordingly.

\subsection{Comparative Analysis Against Prior Systems}



AgentHeal achieves a mean end-to-end remediation time of 2.98~s ($\sigma=0.23$~s), compared to reported MTTR ranges of 2--5 minutes for threshold-based systems such as Keptn \cite{keptn} and Kubernetes HPA \cite{hpa}, and approximately 45 minutes for manual operations \cite{dora2024} (Table~\ref{tab:mttr}). Isolation Forest \cite{isolationforest} detects anomalies in 2.26~ms compared to the 50--200~ms range reported for AIOps deployments \cite{aiops}, though we again note this speed advantage reflects local in-memory inference rather than a distributed production comparison. Unlike static analysis tools such as Bandit \cite{bandit} and SonarQube \cite{sonarqube}, which cannot correlate findings with runtime impact or generate binding fixes, AgentHeal's Shift-Left engine both blocks non-compliant merges and autonomously generates a remediation PR via Gemini 2.0 Flash \cite{gemini2}.

\section{Conclusion}

This paper presented AgentHeal, a dual-engine agentic AI platform integrating OWASP Top 10:2021-aligned Shift-Left PR intelligence with Shift-Right Kubernetes self-healing. Across 15 repeated trials on four synthetic failure scenarios, the system achieves mean end-to-end remediation times of 2.66--3.25~s with Isolation Forest detection latencies of 2.18--2.35~ms. The Shift-Left engine achieves 98.5\% precision and 97.5\% recall on a 50-PR synthetic evaluation set. A single illustrative case study on a live public PR pair additionally shows the pipeline detecting 14 injected OWASP-category flaws and producing a fully compliant auto-fix PR; this case study is qualitative and not part of the statistically powered evaluation. Several limitations remain and should guide interpretation of these results. Scale: all Shift-Right experiments were conducted on a single-node \texttt{kind} cluster, not a multi-node or multi-zone production environment, so reported latencies may not represent real distributed deployments. Evaluation corpus: four synthetic failure scenarios, 50 self-curated PRs, and one live PR pair are insufficient to claim general reliability, since self-curated test cases make precision/recall easier to achieve than organic, adversarial, or stylistically diverse real-world code. Detection generality: several OWASP rules, notably A04 and A05, currently rely on matching specific function or variable names observed in our own test fixtures rather than general data-flow analysis, and would not generalize to differently-named equivalents without further engineering. Compliance scoring calibration: the severity weights used in the compliance score have not been validated against expert-labeled severity judgments or sensitivity-tested against alternative weightings. Statistical treatment: while we report mean and standard deviation for timing metrics, we do not apply formal hypothesis testing against baselines such as HPA, as we did not co-measure baseline systems on the same infrastructure. LLM non-determinism: Gemini 2.0 Flash is proprietary and non-deterministic, so a production deployment on the critical remediation path would need strict timeout handling, deterministic fallback, and output validation. OWASP taxonomy currency: this work targets OWASP Top 10:2021 \cite{owasp2021}, and OWASP has since released a revised Top 10:2025 \cite{owasp2025} with renumbered and, in some cases, redefined categories, to which the current rule set has not yet been remapped.

Future work will investigate evaluation on production Kubernetes traces from multi-node AKS/GKE clusters, formal statistical comparison against HPA and Keptn on shared infrastructure, extending the federated RL protocol for multi-cluster telemetry aggregation, generalizing the OWASP detection rules beyond name-based heuristics toward data-flow/taint analysis, empirically calibrating the compliance-scoring severity weights, remapping the OWASP rule set to the Top 10:2025 taxonomy \cite{owasp2025}, integrating live vulnerability feeds such as NVD \cite{nvd}, OSV \cite{osv}, and GitHub Dependabot \cite{dependabot} in place of the current curated CVE list, and evaluating the Shift-Left engine on a larger sample of public open-source repository PRs.

The complete codebase is publicly available at \url{https://github.com/AadiHaldar/Agentic-AI-Self-Healing-Cloud-Infrastructure} and deployed at \url{https://pr-review-agent.wonderfulflower-41d6d2a5.eastasia.azurecontainerapps.io}.
